# 设计提案：顶层组合治理（人只做管理/审核/决策）

> 2026-11-21。用户约束：一人手里常有 4~6 个项目，精力无法逐任务投入，**只参与顶层的管理 / 审核 / 决策**。
> 本文是设计提案（不改 spec）。凡涉及 spec 契约变更处已标注，须用户批准后另行修改 `docs/spec.md`。

## 0. 命题
**人的「决策税」要随项目数近似恒定，而不是线性增长。**
6 个项目不能让人每天做 6×N 次决策。目标：**每项目每天上升到人的决策 ≤ 0.2 次（≈5 天 1 次），6 项目合计每天 ≤ 1~2 次**，其余全部由系统自治并留痕。

## 1. 三条总原则
1. **默认自治**：任务级的事（技术选择、命名、拆分派工、返工、commit、内部读写）系统自己扛，**不进人的视野**。
2. **例外升级**：只有「顶层 / 阻塞 / 不可逆 / 超预算 / 低于信心」才升到人；且升级要**嚼碎成一句话 + 推荐 + 影响**。
3. **预授权**：能在开工时用「授权档位」一次性约定的，就不在运行中逐次问（对齐 T3 permission modes + Autoloop push policy）。

## 2. 分层委托（L0 → L3）
- **L0 执行 Agent**：在既有治理下自己执行（预算预留、一次性 capability、危险操作守门）。
- **L1 项目队长 / 项目经理 Agent**：项目内拆分、派工、返工、阶段推进、技术决策。**不需要人**。
- **L2 组合主管 Agent（Portfolio Supervisor，新增）**：跨项目巡检、聚合同类升级、把「要不要管」先嚼成「建议动作 + 依据 + 影响」，只把真正顶层的推给人；可代做低风险决定（如暂缓/驳回低危项），**但不能代替人做不可逆 / 预算 / 范围变更**。
- **L3 人（你）**：只碰下面第 3 节的 5 类顶层事项。

> 对齐三家共性：**你是"单一对话人"的唯一对象 = 组合主管 Agent**；子 Agent 永不直接找你。

## 3. 只有这 5 类上升到人（决策税清单）
| 类 | 触发 | 处理 |
|---|---|---|
| **A 契约** | 项目开工确认 spec/目标/验收；或运行中范围/验收变更 | 首次开工做一次；之后除非变更，**不再打扰** |
| **B 验收** | 里程碑 / 最终验收 | 默认档满足证据即**自动过**；只有 `托管档` 才要人点 |
| **C 预算** | 超预算/额度、现金账单「未知待核对」 | 阈值内自动；超阈值/未知才问 |
| **D 不可逆** | 对外发送/发布、合并主干、删除、付款、上传敏感物 | 仅在**未预授权**时问（一次授权可覆盖同类批次） |
| **E 异常** | 连续失败、卡住、指标回归×N、Reviewer 连拒、Phase error | 升级为「要不要改策略/改范围/止损」的决策 |

**排除清单（自动、不惊动人）**：日常技术选择、实现方案、子任务派发、代码返工、命名、commit、内部读写、测试运行。这些只在审计日志里可回看。

## 4. 授权档位（AutonomyProfile）—「少管」的主开关
每项目**开工时选一次**，全局默认 + 项目覆盖：

| 档位 | 行为 | 适合 |
|---|---|---|
| **自动档 `auto`（默认）** | 测试 + 独立审阅通过即自动进入下一阶段、**自动验收**、预算内自动合并；仅 A/C/D/E 升级 | 成熟项目、批量托管 |
| **托管档 `managed`** | 日常全自动；**阶段/最终验收要人点**，其余 A/C/D/E 升级 | 想守住关键节点 |
| **监督档 `supervised`** | 关键命令/改动要人批（≈T3 Supervised），适合高风险/新项目 | 刚上手、敏感项目 |

**三重阈值决定自动 or 升级**：单笔花费 < `spendCap`、风险等级 < `riskCap`、Agent 信心 ≥ `confidenceFloor` → 自动；否则升级。

## 5. 统一「组合收件箱」+ 打扰预算
- **一屏看 6 个项目**，按「**需你拍板 / 健康进行中 / 有风险 / 待你验收**」分组（对齐 HiFox 收件箱，但升级为 **portfolio 级**，不是每项目一个）。
- 每条 = **一个决策项卡片**：项目名 · 一句话 · **推荐动作** · 依据 · 影响 · 一键（批准/驳回/暂缓）· **超时默认动作**。
- **打扰节奏**：默认只做**晨间一份 digest**；仅「阻塞 / 不可逆 / 超预算」实时推（飞书决策卡，复用现有 S10 通道）。
- **打扰预算**：每项目每天最多 `maxInterruptsPerDay`（默认 2），超出合并进 digest；**决策/错误类不可被静默**（生命线，照 Autoloop）。
- **超时默认**：人不回 → 阻塞项保持暂停、不可逆项保持不动、非阻塞项按建议推进。**绝不静默卡死，也绝不擅自做不可逆动作。**

## 6. 数据模型 / 接口（提案，不破坏「单一 Engine 写入」）
- `Portfolio { ownerId, projectIds[] }`
- `AutonomyProfile { projectId, mode, spendCap, riskCap, confidenceFloor, autoAccept, maxInterruptsPerDay }`
- `EscalationItem { id, projectId, kind: A|B|C|D|E, severity, summary, recommendation, evidence, impact, createdAt, deadline, defaultAction }`（跨项目聚合）
- 复用现有 `FeishuDecisionCard`，增加 `recommendation / impact / defaultAction` 字段。
- **约束不变**：组合主管/收件箱只**产生 escalation 与 recommendation**；最终决定仍经**唯一 Engine** 写入（REQ-003）；危险操作仍走一次性授权（REQ-007）。

## 7. 与大铭现状映射
**已可直接支撑**：
- 四件套（REQ-001）= 顶层设定（A 类，一次）。
- 独立验收按确定性证据（REQ-009）= B 类自动过。
- 危险操作一次性授权（REQ-007）= D 类。
- 预算预留/结算、现金未知保留（REQ-006）= C 类阈值。
- 飞书决策卡（REQ-011，已真跑）= 决策卡通道。

**需新增（P0，现有 spec 内可做原型）**：跨项目收件箱 + 打扰预算 + 自动验收门槛 + 决策卡加「推荐动作 / 超时默认」。

**需 spec 变更（提交你审批，我不得自行改 spec）**：新增一条 REQ「**组合治理 / 授权档位 / 顶层决策边界**」，并相应修订 REQ-001/009/011 的验收表述与 DoD——即把"人机协作"从"逐任务审批"正式定为"**人仅顶层组合治理**"。

## 8. 落地顺序
- **P0（现行 spec 内原型）**：统一收件箱聚合 + Autoloop 式打扰策略 + 自动验收门槛 + 飞书卡「推荐/超时默认」。
- **P1（需 spec 审批）**：Portfolio Supervisor + AutonomyProfile 引擎 + 组合视图。
- **P2**：跨项目资源冲突 / 优先级重排 / 依赖调度。

## 9. 度量（人工决策税 KPI）
- 每项目每天需人拍板次数（目标 ≤ 0.2；6 项目 ≤ 1~2/天）——**核心指标**。
- 打扰预算命中率、自动验收比例、升级响应时延、自动决定回看率。

## 10. 边界（防"少管"退化成"失控"）
- 自动验收**永远**以 REQ-009 确定性证据 PASS 为前提，证据不过不自动过。
- **不可逆 / 预算未知 / 范围变更永不自动**，必须人拍板。
- 所有自动决定进审计，人可一键回看「系统替你做了什么」。
