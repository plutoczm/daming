# Impeccable — 设计审查、UX Audit、视觉打磨（项目加工版）

> 定位：把“看着还行”的页面审成“经得起细看”的页面。审查先于动笔，修复落到令牌与组件。

## 何时使用
- 对 `apps/web` 任一页面做改版前的 UX/视觉审查。
- 需要给问题分级（P0 阻断 / P1 明显 / P2 打磨）并给出具体修复。
- 想把“AI 味”页面打磨成有克制的控制面。

## 审查顺序（每一层都要有证据）
1. **信息架构**：一个导航项 = 一个独立页面；页面标题唯一，不与面包屑重复。
2. **层级**：标题 / 区块 / 正文 / 辅助 四级分明；一屏最多一个视觉焦点。
3. **间距节奏**：使用 4/8/12/16/24/32 阶梯；同类元素间距一致；卡片内边距统一。
4. **对比与色彩**：正文 ≥ 4.5:1，大字 ≥ 3:1；主色只用于主按钮/激活/关键数字/链接。
5. **状态覆盖**：空态、加载态、错误态、极端数据（0 / 1 / 很多 / 超长文本 / 大数字）都要成立。
6. **对齐与光学**：左对齐网格；数字用等宽/tabular；截断加省略号。
7. **动效克制**：只为“因果/位置/状态”服务；无炫技光斑；尊重 `prefers-reduced-motion`。
8. **可访问性**：焦点可见、键盘可达、`aria-current`/`aria-live`/语义标签齐全。

## 反 AI 味清单
- 不堆渐变、发光、彩色图标墙；一页一个视觉焦点。
- 不写满解释文字；空态 = 插画 + 一句话 + 一个下一步动作。
- 不用“示例数据 / 离线演示”当首屏主路径。
- 每张卡只回答一个问题；数字用 tabular-nums。

## 输出
- 问题表：`id | 位置 | 现象 | 严重度 | 修复`。
- 修复落到令牌或组件，并留改版前后截图证据。
